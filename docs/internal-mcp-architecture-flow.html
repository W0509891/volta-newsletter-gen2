Next.js OAuth Shim
/authorize Validates client_id, allowed redirect URI, and S256 PKCE challenge.
Signed short-lived code Creates a stateless HMAC-signed authorization code with 5 minute expiry.
/token Verifies the code, redirect URI, client ID, and PKCE verifier.
Bearer token issued Returns the configured VOLTA_MCP_TOKEN as the MCP access token.
MCP Transport + Tools
/mcp/volta route Checks bearer token, applies per-client rate limiting, and sets CORS headers.
Streamable HTTP transport WebStandardStreamableHTTPServerTransport connects request traffic to the MCP server.
createVoltaMcpServer() Registers resources and tools for content, submissions, news, delivery, newsletters, and consent.
Structured responses Tools return human-readable text plus structuredContent for chatbot planning.
Volta Systems
Postgres Stores newsletters, content, revisions, consent records, news candidates, sources, links, and audit logs.
Consent and eligibility services Publication-sensitive actions check approval state before Mailchimp sync or send.
Render pipeline Pug templates and Juice produce table-safe, inline-styled email HTML.
Mailchimp Creates or updates campaigns, uploads rendered HTML, sends campaigns, and fetches reports.

The chatbot never receives direct database credentials. It only sees MCP resources/tools exposed by the server, and the server enforces authorization, rate limits, validation schemas, and publication gates.

Chatbot Connection Sequence

1

Configure the MCP server URL

The chatbot is given the public server URL, typically https://your-domain.com/mcp/volta.

2

Trigger protected-resource discovery

The first unauthenticated MCP request returns 401 and a metadata pointer: /.well-known/oauth-protected-resource/mcp/volta.

3

Run OAuth code flow with PKCE

The client opens /authorize with response_type=code, client_id=volta_user, a Claude callback URI, and an S256 challenge.

4

Exchange code for token

The client posts to /token with the authorization code and PKCE verifier. The server validates both and returns a bearer token.

5

Use MCP tools

Requests to /mcp/volta include Authorization: Bearer <token>. The route creates a MCP server instance and executes the requested tool.

Core Components

Auth and Discovery

The MCP endpoint advertises OAuth metadata through WWW-Authenticate. The authorization shim supports chatbot clients that expect standards-shaped authorization server discovery and PKCE.

/.well-known/oauth-authorization-server /authorize /token

MCP Runtime

The Next route runs in Node.js, accepts GET, POST, DELETE, and OPTIONS, and delegates each authorized request to the Model Context Protocol SDK streamable HTTP transport.

Bearer auth Rate limit: 120/min CORS enabled

Business Services

MCP tools call existing service modules rather than bypassing app rules. This keeps consent, revision tracking, publication eligibility, Mailchimp sync, and status transitions consistent between the admin UI and chatbot workflows.

Postgres Mailchimp Slack/Discord

Security Boundaries

  • Allowed redirect URIs: configured by VOLTA_OAUTH_REDIRECT_URIS and checked before issuing an authorization code.
  • PKCE only: /authorize requires code_challenge_method=S256; /token validates the matching verifier.
  • Signed stateless code: the authorization code is HMAC-signed with the MCP token secret and expires after five minutes.
  • Protected MCP route: /mcp/volta rejects missing or wrong bearer tokens before creating the MCP server transport.
  • Publication gates: Mailchimp sync/send call evaluateNewsletterPublicationEligibility before external publication.
  • Database user: volta_emails should have app DML permissions on current tables, not blanket schema administration.

Example Chatbot-To-MCP Journey

Curator asks the chatbot

"Find approved AI lab stories, create a dispatch draft, render it, and sync it to Mailchimp for review."

Server-side guardrail

Even if the chatbot asks to send immediately, newsletter.sync_mailchimp and newsletter.send re-check eligibility, consent status, and campaign state before acting.

  1. The chatbot calls content.search and news.search to gather candidates.
  2. It uses newsletter.create and newsletter.add_item to assemble a draft issue.
  3. It calls newsletter.render, which syncs tracked links and renders template HTML.
  4. It calls newsletter.sync_mailchimp, which runs eligibility checks, creates or updates a Mailchimp campaign, uploads HTML, and stores campaign IDs back in Postgres.
  5. A human curator can preview in Mailchimp or the admin UI before explicitly invoking newsletter.send.
