Control plane
1Claude web client

Connect to Volta MCP

Requests /mcp/volta without a credential and receives a 401 challenge.

2Resource metadata route

Discover OAuth server

/.well-known/oauth-protected-resource/mcp/volta identifies the protected resource and issuer.

3GET /authorize

Validate client + PKCE

Checks volta_user, callback allowlist, state, response type, and the S256 challenge.

4POST /token

Exchange signed code

Verifies the short-lived authorization code and PKCE verifier, then returns a bearer token.

5MCP HTTP gateway

Accept protected request

/mcp/volta validates Authorization: Bearer and applies request rate limits.

6Claude web client

Load Volta tools

The client lists typed MCP tools and can begin an authenticated operational session.

Authentication contract

  • Claude authenticates to Volta with a bearer token obtained through Authorization Code + PKCE.
  • The OAuth shim is a compatibility layer; /mcp/volta remains the enforcement point.
  • Client ID, redirect URI, code challenge, expiry, and signature are validated server-side.

Publication contract

  • MCP tools call the same newsletter service gates as the application.
  • Sync creates or updates a Mailchimp draft; send is a separate explicit operation.
  • Consent, eligibility, duplicate-send, and campaign-state checks stay inside Volta.

Observability contract

  • Tool results return structured IDs, URLs, status, and actionable errors to the chatbot.
  • Database audit and delivery records preserve operational history.
  • Mailchimp remains the source for delivery metrics; Volta stores its linked campaign identity.
