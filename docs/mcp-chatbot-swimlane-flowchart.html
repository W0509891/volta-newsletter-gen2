Volta MCP Chatbot Swimlane Flowchart

A step-by-step operational flow for connecting an AI chat client to the Volta Newsletter MCP server, authorizing it through the current PKCE shim, and executing protected newsletter workflows.

Lane Legend

User and AI chatbot client
OAuth discovery and token endpoints
MCP route, transport, and tools
Volta business services
Postgres, Mailchimp, Slack, Discord
User + AI ChatbotClaude web client or another MCP-aware assistant

External SystemsDatabase, Mailchimp, Slack, Discord
T0
Setup
Add MCP server URL User configures chatbot with https://domain.com/mcp/volta.
Initial protected request /mcp/volta rejects missing bearer token with 401.
T1
Discover
Read auth challenge Chatbot follows WWW-Authenticate resource metadata pointer.
Protected resource metadata /.well-known/oauth-protected-resource/mcp/volta returns resource and authorization server.
T2
Authorize
Start PKCE flow Client opens /authorize with client ID, redirect URI, state, and S256 challenge.
Validate auth request Checks client_id, allowed redirect URI, response_type=code, and PKCE method.
T3
Code
Receive callback Chatbot receives code and original state at its callback endpoint.
Issue signed code Server creates a short-lived HMAC-signed stateless code tied to challenge and redirect URI.
T4
Token
Exchange authorization code Posts to /token with code, client ID, redirect URI, grant type, and PKCE verifier.
Verify PKCE and code Confirms signature, expiry, client binding, redirect binding, and verifier hash.
Bearer token ready Token response returns VOLTA_MCP_TOKEN as the bearer credential for MCP.
T5
Tool Call
Ask operational question Example: "Create a draft newsletter from approved AI Lab stories and sync it to Mailchimp."
Authorize MCP request Route checks Authorization: Bearer, validates token length/config, and rate limits by client IP.
Resolve tool schema MCP server exposes typed tools such as content.search, newsletter.create, and newsletter.render.
T6
Curate
Call content and news services Searches approved content, founder submissions, news candidates, revisions, and consent records.
Read Postgres Uses the app database user to query newsletter, content, news, contact, consent, and audit tables.
T7
Assemble
Create and render draft newsletter.create, newsletter.add_item, and newsletter.render build HTML through Pug and Juice.
Write Postgres Stores draft newsletter, item ordering, tracked links, rendered HTML, and status updates.
T8
Guard
Eligibility checkpoint newsletter.sync_mailchimp and newsletter.send call publication eligibility checks before external publication.
T9
Publish Prep
Sync to Mailchimp Creates or updates campaign, uploads rendered HTML, then saves campaign ID, web ID, and archive URL.
Mailchimp draft campaign Marketing API uses access token or API key, server prefix, audience/list ID, sender name, and reply-to.
T10
Human Review
Curator reviews Human checks rendered newsletter and Mailchimp draft before any final send.
Return structured result MCP returns JSON text plus structuredContent including IDs, URLs, and success/error state.
T11
Send
Explicit send request User asks chatbot to send, or uses admin UI after review.
newsletter.send Tool request flows through auth, schema validation, and server-side service gates.
Final send gate Rejects already sent campaigns and any ineligible newsletter content before calling Mailchimp.
Mailchimp sends campaign On success, app marks newsletter sent and archives included content items.
T12
Observe
Chatbot reports status User receives result, campaign metadata, or actionable error message.
Reports and digests Optional tools fetch Mailchimp reports, build Slack/Discord digests, and record link clicks.
Mailchimp + Slack/Discord External systems provide campaign metrics and internal notification channels.

Primary Happy Path

  • Chatbot discovers metadata after a protected MCP request.
  • OAuth shim issues a signed, short-lived code and validates PKCE at token exchange.
  • MCP route accepts the bearer token and runs typed Volta tools.
  • Newsletter sync and send preserve the same eligibility checks used by the app.

Failure Branches

  • Unknown redirect URI returns invalid_request.
  • Wrong client ID returns unauthorized_client.
  • Expired or tampered code returns invalid_grant.
  • Missing or wrong bearer token returns 401 from /mcp/volta.
  • Ineligible newsletter content blocks Mailchimp sync/send.
